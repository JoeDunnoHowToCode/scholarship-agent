# 前端 UI/UX 修正計畫（2026-11-08）

狀態：**已核准（11-08）**。待決定 1 選丙（ADR-090）、2 選乙（ADR-091）、3 選乙（ADR-092）；B1 的按鈕放在標題右側同一列（使用者指定）。

## 怎麼找出來的

- 讀過五頁與外框：`App.tsx`、`ScholarshipList.tsx`、`ScholarshipDetail.tsx`、`Ask.tsx`、`Profile.tsx`、`Notifications.tsx`
- 用瀏覽器實測（開發資料庫，1280px 寬）：
  - 列表 191 筆，一次全部顯示：還能申請 69、時間待確認 100、已截止或不適用 22
  - 打開「只看開放中的」剩 56 筆；點進一筆再按上一頁，開關變回關閉，又回到 191 筆
  - 從列表捲到中間再點進詳細頁，詳細頁開在捲動位置 1067px，不是頁首
  - 列表卡片能點的只有標題連結，高 18px；卡片其他地方點了沒反應
- 對照的原則：Emil Kowalski 的 `break-ui`、`ui-cheatsheet`（上一輪已修申請期、補助、文件三個表格）

## 使用者要完成的事（設計依據）

1. 在列表裡快速找出「現在能申請、適合我」的獎學金
2. 打開一筆，馬上知道：什麼時候申請、拿多少、要交什麼、去哪裡申請
3. 回到列表繼續看下一筆，不要從頭再找

下面的問題依這三件事排優先順序。

嚴重程度：**阻礙**（擋住主要任務）、**難用**（做得到但費力）、**粗糙**（看起來不對，不影響任務）。

## 待決定（使用者選）

### 待決定 1：詳細頁的區塊順序

背景：一頁有 6 個區塊。順序決定使用者先看到什麼；放越前面越容易看到，放後面要捲動。

| 選項 | 順序 | 好處 | 代價 |
| --- | --- | --- | --- |
| 甲 維持現狀 | 評分 → 申請期 → 資格 → 補助 → 文件 → 變更紀錄 | 不用改；評分理由一進來就看到 | 申請期、補助、文件要往下捲 |
| 乙 照行動順序 | 申請期 → 補助 → 文件 → 資格 → 評分 → 變更紀錄 | 符合「何時、多少、交什麼」的思考順序 | 評分理由要捲到下面才看到（分數本身仍在 B2 的摘要列） |
| 丙 摘要＋分頁籤 | 摘要列下方用頁籤切換：申請／資格／評分／紀錄 | 頁面短，不用捲動 | 要多點一下；不能一次捲完整頁；多一個元件 |

### 待決定 2：個人資料的國家怎麼輸入

背景：目前國籍與想去的國家都是自由輸入國碼。後端已有國碼對中文名稱的資料（列表的國家選單就是用它）。

| 選項 | 做法 | 好處 | 代價 |
| --- | --- | --- | --- |
| 甲 維持輸入國碼 | 不改，只在欄位下方加說明與範例 | 不用改 | 打錯要存檔後才知道 |
| 乙 下拉選單 | 國籍用單選、想去的國家用多選，選項顯示中文名稱 | 不會打錯 | 多選元件較複雜（shadcn 沒有現成的多選）；要一支 API 提供完整國家清單 |
| 丙 輸入時檢查 | 保留輸入框，打完立刻顯示對應的中文名稱，或「查不到這個國碼」 | 改動小，打錯馬上知道 | 還是要知道國碼 |

### 待決定 3：通知要不要能點回獎學金詳細頁

背景：通知（events 表）目前只存標題、內文、外部網址，沒有存是哪一筆獎學金。

| 選項 | 做法 | 好處 | 代價 |
| --- | --- | --- | --- |
| 甲 不做 | 維持外部網址 | 不用改後端 | 看到通知還要自己去列表找 |
| 乙 通知 API 多回傳獎學金編號 | events 加 `scholarship_id` 欄位（要遷移），舊通知是空的 | 新通知都能點回詳細頁 | 動到資料表、通知產生流程與測試；舊通知點不回去 |

## 不在範圍

- 列表分頁或虛擬捲動：191 筆實測不卡，等超過 500 筆再看
- 深色模式、動畫：目前沒有需求；動畫原則（emil-design-eng）大多用不上
- 卡片上「開放中／即將開放」改成彩色徽章：需要 API 多一個狀態欄位，另案處理

## Claude 自行決定（小問題，請事後檢查）

1. A2 整張卡片可點用卡片的 onClick，不用「連結的 ::after 蓋住整張卡片」：CardHeader 是 CSS container，會把 ::after 限制在標題那一塊（實測點內文沒反應）。選取文字時不換頁
2. B3 頁籤內容只在選到時才畫：Base UI 會等離場動畫跑完才移除舊面板，瀏覽器分頁在背景時動畫不跑，新舊內容同時出現（實測）
3. B2 詳細頁 API 多回傳 `deadline_line`、`amount_headline`，用和列表卡片同一個函式算，測試確認兩邊一樣（`test_detail_summary_db.py`）。綠燈的程式碼被同時在 main 上工作的另一個 session 一起提交進 `de16bce`（發現於 11-08，內容正確，沒有改寫歷史）
4. 加了頁籤後前端打包 502 kB，超過 Vite 的 500 kB 提醒；本機使用，先不拆檔
5. 「還沒評分」時評分頁籤顯示提示，請先填個人資料
