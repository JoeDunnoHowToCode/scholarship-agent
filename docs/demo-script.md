# 示範影片腳本（約 3 分鐘）

錄影前準備：

- `docker compose up -d`；`cd backend && uv run uvicorn app.main:app`；瀏覽器開 `http://127.0.0.1:8000/`
- **不要拍到個人資料頁、評分理由**（ADR-001、記憶裡的規則）。列表的分數可以先在設定頁把門檻調高，或錄之前把個人資料清空再錄，錄完復原
- 準備一則 Telegram 通知的截圖（每日檢查報告），只留標題和來源數字
- 終端機字體放大，背景用淺色

| 時間 | 畫面 | 旁白（重點） |
| --- | --- | --- |
| 0:00–0:20 | 首頁的獎學金列表 | 「這是一個幫我找歐洲碩士獎學金的 AI agent。它每天自己檢查 250 個官方來源，抽出截止日、國籍資格、金額，依我的條件排序。」 |
| 0:20–0:50 | 點一筆獎學金，看詳細頁的「資格」頁籤，把滑鼠移到原文引用 | 「AI 抽出的每個關鍵欄位都附逐字引用，程式會確認這句話真的在官網原文裡；找不到依據的會標成待確認，不會當成事實。」 |
| 0:50–1:20 | 紀錄頁：點開一次「逐校找」的「看每一步」 | 「發掘新來源的 agent 是我自己寫的迴圈：它從官方大學名單出發，打開學校首頁、切到英文版、找到獎學金頁再提交。每一步都記下來，可以事後追查它為什麼這樣做。」 |
| 1:20–1:45 | 設定頁：agent 加的來源清單、開關；斷路器 | 「agent 交的只是候選，要通過四條規則和內容去重才會加入；看到不對的，我在這裡關掉。每次 AI 呼叫都記錄費用，到每月上限會自動暫停。」 |
| 1:45–2:10 | Telegram 的每日檢查報告截圖 | 「每天檢查完會送一則報告：檢查了幾個來源、哪些抓不到、今天 AI 花了多少。」 |
| 2:10–2:35 | `docs/eval/` 的評估報告 | 「要換模型之前，我用固定的樣本和同一份網頁快照，比較兩個模型的有根據率、穩定度和一致率，再人工抽查兩邊不一樣的地方。」 |
| 2:35–3:00 | GitHub：CI 綠勾、`docs/adr.md` 捲動 | 「每次推送都在 GitHub Actions 跑 300 多個測試；將近 100 個架構決定都寫成 ADR，記下理由和後果。」 |

講的時候分清楚：架構與產品的選擇是你做的（ADR 裡寫「使用者選」的那些），程式由 AI 實作；你負責決定、審查與驗證。
