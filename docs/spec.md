# 規格摘要（第一版）

最後更新：2026-10-09。已依 ADR-001 到 023 調整；和 claude.ai 上的原始規格書不同時，以本檔與 `docs/adr.md` 為準。

## 目標與範圍

- 解決「不知道哪裡有、也不知道適不適合自己」：核心價值是媒合，不只是收集
- 收錄出國相關獎學金：國外政府與機構、台灣政府與機構、國外大學自己的獎學金；不收台灣校內獎學金
- 先做歐洲，英國與北歐優先；使用者本人申請碩士，出發時間未定，所以同時追蹤最近兩個入學年度
- 第一版只有使用者本人，跑在本機；資料模型預留多人與公開

## 第一版要做

- 自動收集：來源清單為主，每週搜尋發掘新來源；候選來源經使用者核准才加入
- 抽取與驗證，並整理每個獎學金的文件清單與具體要求（字數、格式、推薦信封數）
- 依表單填寫的個人條件評分 0–100，附理由與待確認條件；全部列出，不過濾
- Telegram 即時通知：新獎學金、新年度開放、截止前提醒、資料變更
- 網頁：列表（排序與篩選）、詳細頁、個人資料頁、設定頁
- 截止後移到封存區，新年度開放時自動喚回
- RAG：用一句話搜尋獎學金；對抓下來的原文提問，回答附出處（ADR-032，排在哪一天待決定）

## 第一版不做

履歷上傳解析（ADR-012）、Telegram 互動按鈕（v1.1）、申請進度看板與缺件追蹤（v2）、AI 改履歷與自傳（v3）、Gmail 追蹤結果（v4）、會員登入與雲端部署（公開版）

## 資料模型

共用資料（ADR-023）：

- sources：名稱、網址、類型（政府、機構、大學、彙整網站）、國家、抓取方式、檢查頻率、上次內容雜湊、是否啟用、發現方式（種子或搜尋）、狀態（候選或已核准）
- scholarships：原文與中文名稱、提供單位、留學國家、學位、領域、補助內容、金額、台灣籍資格（yes、no、unclear）、台灣專屬條件、語言要求、其他資格、是否需先錄取、官方網址、最後驗證時間、狀態（使用中或封存）、extracted（JSONB，完整抽取結果）
- cycles：入學年度與學期、開放日、截止日（UTC 加原始時區）、狀態（預估、即將開放、開放中、已截止）、其他里程碑
- requirements：文件類型、具體要求、必要或選填、原文出處
- snapshots：網址、抓取時間、內容雜湊、檔案路徑、HTTP 狀態
- changes：欄位、舊值、新值、時間、對應快照

個人資料（都有 user_id，ADR-021）：

- profiles：國籍、學歷與學校、科系、GPA 與滿分、畢業日、目標學位與領域、目標國家、語言檢定、工作年資、版本號
- matches：總分、各分項分數、理由、待確認條件、不符合原因、使用的模型、計算時間、個人資料版本
- events：類型（新獎學金、新年度、截止提醒、資料變更）、內容、發送時間與狀態

## 評分

1. 硬性條件由程式判斷，結果是符合、不符合或待確認：國籍、學位、時間、明確門檻（工作年資、年齡、語言最低分）。任一不符合，總分上限 20；任一待確認，上限 80。原文沒提到台灣時一律待確認，絕不推定可以
2. AI 分項評分，每項 0–10：領域契合 30%、條件達成度 25%、補助價值 20%、時程可行 15%、競爭與名額 10%
3. 總分 = min(上限, 10 × Σ 權重 × 分項分數)；溫度 0；只有個人資料版本或獎學金內容變動時才重算

## 通知

- 門檻預設 60 分，設定頁可調，設成 0 就是全部通知
- 同一輪超過 5 則就合併成一則摘要
- 截止提醒：剩 30、14、7、3、1 天各一次，只對達門檻的獎學金
- 資料變更只看重要欄位：截止日、金額、資格、文件要求；排版或錯字修改不通知

## 排程與資料維護

- 每天 08:00 檢查來源清單；每週日搜尋新來源；每天 09:00 跑截止提醒（台灣時間）；電腦關機錯過的排程，開機後補跑
- 抓取後先把文字正規化再算雜湊，沒變就跳過，不花 AI 費用
- 截止後申請期改為「已截止」；沒有其他開放中的申請期就封存，並依去年日期產生「預估」申請期，預估開放前一個月起每週檢查官網

## 開發排程

每一天開始前，先決定 `docs/adr.md` 中排在那一天之前的題目。

- 第 1 天：專案骨架、Docker（Redis、PostgreSQL）、資料表與遷移、Gemini 結構化輸出、第一個單元測試（`docs/day-01.md`）
- 第 2 天：來源清單與抓取、快照與雜湊
- 第 3 天：抽取與驗證者、文件清單
- 第 4 天：合併與去重、申請期、變更紀錄、封存與預估下一輪
- 第 5 天：個人資料表單 API 與評分（硬性條件＋AI 分項）
- 第 6 天：用 RQ 串起每個步驟、rq cron 排程、重試設定
- 第 7 天：Telegram 通知（四種事件、門檻、合併）
- 第 8 天：前端列表、詳細頁、個人資料頁
- 第 9 天：設定頁、成本統計與每月上限、LangGraph 發掘 agent 與候選來源核准
- 第 10 天：評估資料集、比較兩個 Flash-Lite 模型、README 與示範影片

## 成本粗估

- Gemini 3.5 Flash-Lite：每百萬 tokens 輸入 US$0.30、輸出 US$2.50（Gemini API 定價頁）
- 每頁三次呼叫（抽取、驗證、評分）合計約輸入 14,000、輸出 1,800 tokens，約 US$0.009
- 第一次建檔約 270 頁，約 NT$75；之後假設每月約 50 頁有變動，約 NT$14（以 1 美元兌 32 元粗估）
