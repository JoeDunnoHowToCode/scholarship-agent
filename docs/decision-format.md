# 向使用者說明架構決策的格式

使用者的目標是學會 AI 工程師的架構思維，所以每個決策都要寫到「沒碰過的人看完也懂，而且知道怎麼選」。

## 說明的結構

1. 這題在決定什麼：一兩句話
2. 先懂的概念：用比喻或這個專案的例子解釋背景知識，需要時附程式碼或資料夾結構
3. 選項：通常 3 到 4 個，每個都寫
   - 怎麼運作
   - 好處
   - 代價
   - 在這個專案會怎樣
4. 選了會怎樣：用這個專案的具體情境做比較表（例如「加入 LINE 通知時要改哪裡」）
5. 對照品質屬性：盡快做出能用的版本、學習價值與作品集、結果準確可信
6. 可逆性：難回頭、中等或可回頭；拿不定時該怎麼想
7. 可以給「參考組合」，但要說明這是參考不是答案

## 問法

- 用題號與 A、B、C 讓使用者好回答，也接受使用者自己的理由
- 使用者的選擇若和品質屬性、限制條件或先前的 ADR 衝突，要明確指出並說明後果
- 一次問的題目不要太多；同一時機的題目一起問

## 決定之後

把決定追加到 `docs/adr.md`，並從「待決定」表格移除該題：

```markdown
### ADR-NNN 標題
- 決定：
- 理由：
- 後果：
```
